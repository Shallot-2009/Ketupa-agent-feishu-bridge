# 公开接口代码安全体检

检查日期：2026-10-19。范围为本包接口源码、配置示例、依赖锁、发布脚本与 CI。未提供远端仓库配置或历史，不能据此判断既有远端分支、提交历史和 GitHub 安全设置。

## 新增安全控制

- 逐文件模型许可、用户与会话 ACL 和 SHA-256 校验；策略变化切断旧模型上下文。
- 模型只生成候选 JSON；固定 schema 与真实附件绑定后才能显式提交。
- 消息处理前持久收据、预览提交 claim、任务运行 claim，防止回包失败或重投重复执行。
- 双 runtime 实例互斥、有界队列、隐藏子进程树取消、重启保守标记 interrupted。
- 取消标志在状态读取及交付时生效，避免并发完成把已取消任务重新开放输出。
- 群文本必须匹配已确认的机器人 Open ID；身份缺失或 @ 信息不完整时拒绝处理，避免空值误判。

## 已检查的边界

本次增加知识授权、任务预览、后台队列、取消恢复、消息收据和上下文重置的行为测试；最终测试数量、依赖体检与源码扫描以本次 release/VALIDATION.json 所绑定的 ZIP 哈希为准。该记录不在源码包中，打包后需针对同一哈希重新验收。

- 用户和会话双白名单，默认全部拒绝；按会话与发送者隔离上下文、附件和任务。
- 默认禁止向模型发送文字；附件不自动上传模型。凭据经本机环境读取，不放进公开包。
- 用户或模型文字不拼入 shell。执行器由可信配置指定，只通过规范 JSON 接收参数。
- 输出只从所属任务的 output 交付；限制文件数量和大小，拒绝路径逃逸与符号链接。
- 源码白名单打包，排除 runtime、登录态、凭据、客户文件、核心引擎和本机二进制。

## 使用者仍需承担的配置责任

1. Codex read-only 不等于“只能读工作目录”。使用独立系统账号或容器、独立模型登录目录，不挂载私人核心和其他账号凭据。已有 MCP、插件或外部执行器的权限不能靠提示词隔离。
2. 外部执行器是可信程序；本包不证明其物理精度或限制其全部系统权限。先验证固定 workflow，再启用真实执行。
3. 授权用户也可能大量提交任务，导致磁盘增长或模型费用；按业务设置额度、磁盘监控和保留期限。本最小接口包未提供完整配额管理。
4. GitHub 开启可用的 Secret scanning / Push protection，保护默认分支并审查 PR。自动扫描不能识别所有形式的隐私；提交前人工确认新增内容。
5. 未通过本次体检证明真实消息交付、模型推理或求解成功。平台授权和真实链路需按配置手册分别验收。

## 重复体检

```sh
npm ci --ignore-scripts
npm test
npm audit --omit=dev --audit-level=high
npm run release:check
node scripts/release-check.mjs --tracked
npm run release:pack
```

`--tracked` 需要在本公开项目的 Git 仓库根执行；没有 Git 仓库时先做源码检查与打包。检测到未知文件或私有信息时禁止继续发布；检查日志仅报告相对文件名和规则。
